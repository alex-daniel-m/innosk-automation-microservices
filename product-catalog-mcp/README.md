# Product Catalog MCP

## Init Project

```
mkdir product-catalog-mcp
bun init -y
bun add @modelcontextprotocol/sdk @prisma/client @prisma/adapter-pg pg zod
bun add -d prisma typescript @types/node @types/pg
```

## Folder Structure

```
product-catalog-mcp/
├── prisma/
│   ├── migrations/         # Database migration history generated by Prisma
│   └── schema.prisma       # Core Prisma schema defining models, enums, and relations
├── src/
│   ├── application/        # Application layer containing MCP business logic
│   │   ├── dtos/           # Data Transfer Objects & Zod validation schemas for tools
│   │   ├── services/       # Domain services and action handlers invoked by MCP tools
│   │   └── tools/          # MCP Tool definitions and registration manifest
│   └── infraestructura/    # Infrastructure layer and database adapters
│       ├── generated/      # Auto-generated Prisma client artifacts
│       └── client.ts       # Shared PrismaClient instance configured with PostgreSQL adapter
├── .env                    # Local environment variables configuration
├── .gitignore              # Git ignored files and directories
├── bun.lock                # Bun lockfile for reproducible dependency trees
├── main.ts                 # Entry point / application bootstrap script
├── package.json            # Project manifest, scripts, and dependencies
├── prisma.config.ts        # Prisma v7 datasource configuration file
├── README.md               # Project documentation
└── tsconfig.json           # TypeScript compiler configuration
```

## Schema Prisma

Create and define prisma schema file inside `prisma/schema.prisma` folder.

Make sure that at the beginning of the file the configurations look like this:

```prisma
datasource db {
  provider = "postgresql"
}

generator client {
  provider = "prisma-client"
  output   = "../src/infraestructure/generated/prisma"
}
```

## Create configuration file `prisma.config.ts`

```ts
import "dotenv/config";
import { defineConfig, env } from "prisma/config";

export default defineConfig({
  schema: "prisma/schema.prisma",
  migrations: {
    path: "prisma/migrations",
  },
  datasource: {
    url: env("DATABASE_URL"),
  },
});
```

## Generate Prisma Client

In the root project directory, run this command:

```
npx prisma generate
```

## Create Singleton Prisma Cliente

Inside `src/infraestructure/` directory, create a `client.ts` file with the following content:

```ts
import { PrismaPg } from "@prisma/adapter-pg";
import { PrismaClient } from "./generated/prisma/client";
import pg from "pg";

// globalThis in TypeScript
const globalForPrisma = globalThis as unknown as {
  prisma: PrismaClient | undefined;
  pool: pg.Pool | undefined;
};

// Pool
const pool = globalForPrisma.pool ?? new pg.Pool({
  connectionString: process.env.DATABASE_URL,
});

// Instance
const adapter = new PrismaPg(pool);

// Export
export const prisma = 
  globalForPrisma.prisma ?? 
  new PrismaClient({
    adapter,
    log: process.env.NODE_ENV === "development" ? ["query", "error", "warn"] : ["error"],
  });

if (process.env.NODE_ENV !== "production"){
  globalForPrisma.prisma = prisma;
  globalForPrisma.pool = pool;
}
```

## DataSource Configuration in the .env File

You must configure PostgreSQL datasource connection string in the `.env` file.

```env
NODE_ENV="development"
DATABASE_URL="postgresql://user:password@localhost:5432/some_database_name?schema=public"
```

## First Migration

In the root project directory, run this command:

```
npx prisma migrate dev --name init_catalog_schema --create-only
```

After that, we must apply the migration to the database.

```
npx prisma migrate dev
```

## Second Migration

In the root project directory, run this command:

```
npx prisma migrate dev --name add_timestamp_triggers --create-only
```

Previously, we created and applied the `first` migration to the database. THerefor, the second megration doesn't contain any data or SQL instructions generated by Prisma. However, we need the second migration to add custom database configuration that Prisma cannot create automatically, such as triggers or funtions. We must add these manually to the migration file.
